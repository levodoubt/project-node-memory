# 写项目节点知识库（`.nodekb/`）

## 什么时候该写

值得沉淀的：**设计决策与理由**、**踩过的坑（症状 + 根因 + 对策）**、**事实常量**（版本号、路径、阈值、接口字段）、**待办与交接**、**环境和操作手册**。

不该写的：一次性的调试输出、能从代码直接读出来的内容（函数签名、目录列表）、临时状态。判据是「下次换个人/换个会话，不知道这条会不会重做一遍错事」。

## 先读，再写

```
kb_read mode=toc            # 结构 + 每节字符数，几百 token
kb_read target=<TID>        # 按需读一支
kb_search query=...         # toc 里找不到再搜
```

**不要**一次把整库读进上下文。写之前先确认：这个结论是不是已经写在别处了？是的话改那一处，别新开一条（同一结论写两遍，两份迟早打架）。

## 目录怎么分

| 目录 | 放什么 | 判据 |
|---|---|---|
| `doc/` | 主题文档：架构、模块、流程、配置 | 「是什么、怎么运转」 |
| `lessons/` | 踩坑记录 | 「症状 → 根因 → 对策」三行齐全 |
| `todo/` | 未完成事项、阻塞、交接 | 有明确的下一步动作 |
| `index/entry.md` | 总入口与落位约定 | 只放导航，不放正文 |

这张表是「不知道放哪时」的默认答案，**不是白名单**：项目没有待办就别建 `todo/`，需要 `adr/`、`api/`、`runbook/`、`metrics/` 就自己加；节点 `type` 同样自由（`type="decision"`、`type="api"` 都行）。

一个主题一个文件，**单文件取 < 4KB**；变大就按子主题拆成 `## 3.x` 段或独立文件。

## 两种引用，别混

| 写法 | 渲染成 | 用在 |
|---|---|---|
| `[[node="doc:03-build:3.1"]]` | 一个链接，**不复制正文** | 指向另一段结构：「细节见 …」 |
| `[[tscl="fact:abi"]]` | 把 `<tscl id="fact:abi">` 的定义体**替换进来** | 同一句话/同一组数字必须在多处出现 |

```md
<tscl id="fact:abi">
三条硬规则：1) 只用 C ABI；2) 名字加前缀 `fm_`；3) 导出结构体必须定长。
</tscl>
```

规则：

- **同一个 id 全库只能定义一次**，否则 `kb_diag` 报 error（重复定义）。
- id 不能和节点 TID 同名（命名空间冲突 = error）。惯例：值用 `fact:` 前缀，结构用目录前缀。
- 宏体**跨行**时不要内联进表格单元格（diag 会 warning，渲染也会断行）。
- 定义块内部的 `##` **不会**变成节点——它只是文本。

旧写法 `[[TID]]` 仍能解析（有定义时当宏、否则当链接），但 `kb_diag` 会 warning，2.0 移除。
接手老库时按 `kb_diag` 的「旧语法引用」清单逐处改成 `[[node=…]]` 或 `[[tscl=…]]`，改完再跑一次 `kb_diag`。

## TID 规则

- 文件节点：`<目录>:<文件名 slug>`，例如 `doc/03-工程经验与坑.md` → `doc:03-工程经验与坑`
- 显式节点：`<node name="abi">` 里的 `name` 原样就是 TID，可跨文件引用
- 段节点：`## 3.1 xxx` → `<文件TID>:3.1`，是**位置型**的：插一节就漂。链接它只是 warning（指错了跳错节），但**别拿它当需要长期稳定的锚点**——要稳定就写显式节点
- 改名走 `kb_rename`，它会重写全库引用

## 写

```
kb_write target=lessons/003-cp936.md  mode=create  content=...
kb_write target=<显式节点TID>          mode=node    content=...   # 只换 <node> 之间的正文
kb_write target=doc/03-...md          mode=append  content=...
```

- 写完**看返回值里的校验结果**：悬空引用、重复定义、`<node>` 没独占一行，都会当场报回来。看到就修，别留着。
- 改已有内容用 `append` / `node`，不要 `replace` 整篇（会丢掉别人刚写的段落）。
- 新建文件前先 `kb_read mode=toc` 确认没有同主题的旧文件。

## 三个反例

1. 把整段对话贴进 `doc/` —— 记的是过程，不是结论。
2. 同一件事在 `doc/` 和 `lessons/` 各写一份 —— 抽成 `<tscl>` 定义，两处都引用它。
3. 只写「改了什么」不写「为什么」 —— 半年后没人知道能不能改回去。
