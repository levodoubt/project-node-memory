# 写项目节点知识库（`.nodekb/`）

## 什么时候该写

值得沉淀的：**设计决策与理由**、**踩过的坑（症状 + 根因 + 对策）**、**事实常量**（版本号、路径、阈值、接口字段）、**待办与交接**、**环境和操作手册**等。

不该写的：一次性的调试输出、能从代码直接读出来的内容（函数签名、目录列表）、临时状态。判据是「下次换个人/换个会话，不知道这条会不会重做一遍错事」。

## 先读再写

```
kb_read mode=toc            # 结构 + 每节字符数，几百 token
kb_read target=<TID>        # 按需读一支
kb_search query=...         # toc 里找不到再搜
```

**不要**一次把整库读进上下文。写之前先确认：这个结论是不是已经写在别处了？是的话改那一处，不要把同一结论写两遍。

`kb_search` 是词面检索，不是语义检索：中文按 2-gram 切、英文按空白切词，加权命中后再用子串兜底，所以搜**关键词**更有效；命中给 `tid + 片段`，拿到 TID 再 `kb_read`。注意命中行里两个字段不是一回事：`tid` 是**稳定句柄**（拿去 `kb_read` 的那个），`ref` 才是**真正命中的节点**（可能是段节点或更深的块，往往比 `tid` 更具体）——两者对不上时按 `ref` 去定位，别以为 `tid` 就是命中点。

写完跑一次 `kb_diag`，分三档：

| 档         | 含义                                                                              | 怎么处理                   |
| ---------- | --------------------------------------------------------------------------------- | -------------------------- |
| `errors`   | 真损坏：悬空引用、重复 TID、重复定义、树环                                        | 必修，否则库结构已坏       |
| `warnings` | 疑似漂移：旧语法裸引用、位置型 TID 链接、跨行宏进表格、孤儿节点                   | 按需处理                   |
| `advice`   | **没有问题，但是可改进**：碎片文件过多、同一句散在多处、缺入口、缺 H1、段节点过长 | 建议处理，不影响 exit_code |

`advice` 每条都带 `fix`，一次最多报 5 条，**不会让 `kb_diag` 失败**——CI 里可以无视。

样板段落会被当成「重复内容」（如导航句、免责声明）。`.nodekb/diag_ignore.json` 是豁免表：`{"blocks":[...],"lines":[...]}`，两项都是**正则**列表（逐条 `new RegExp(...)`）。按字面匹配要自己转义 `(` `)` `[` `]` `+` `|` `\` 这类元字符；非法正则会被静默跳过、不报错，于是「整段原文直接贴」只对不含元字符的样板有效（`blocks` 比的是归一化空白后的整段文本，`lines` 比的是单行原文）。

## 目录规划

| 目录             | 放什么                           | 判据                           |
| ---------------- | -------------------------------- | ------------------------------ |
| `doc/`           | 主题文档：架构、模块、流程、配置 | 「是什么、怎么运转」           |
| `lessons/`       | 踩坑记录                         | 「症状 → 根因 → 对策」三行齐全 |
| `todo/`          | 未完成事项、阻塞、交接           | 有明确的下一步动作             |
| `index/entry.md` | 总入口与落位约定                 | 只放导航，不放正文             |

这张表是**推荐做法**，你可以自行根据项目实际情况进行规划。如项目没有待办就别建 `todo/`，需要 `adr/`、`api/` 等就自己加；节点 `type` 同样自由。

一个主题一个文件，**单文件建议 1KB - 4KB**；变大就按子主题拆成 H2 标题段或独立文件，过小就合并成多节点文档。

## 两种引用方法

| 写法                          | 渲染成                                         |
| ----------------------------- | ---------------------------------------------- |
| `[[node="doc:03-build:3.1"]]` | 一个链接，**不复制正文**                       |
| `[[tscl="fact:abi"]]`         | 把 `<tscl id="fact:abi">` 的定义体**替换进来** |

```md
<tscl id="fact:sample">
tscl 机制支持段落标记与行内标记
</tscl>

sampletext<tscl id="fact:sample2">tscl 机制支持段落标记与行内标记</tscl>sampletext
```

规则：

- **同一个 id 全库只能定义一次**。
- id 不能和节点 TID 同名。惯例：值用 `fact:` 前缀，结构用目录前缀。
- 定义可以**就地写在正文句子里**：如`当前版本号为：<tscl id="fact:ver">v1.23.45</tscl>，向下兼容 v1.22。`（渲染时标签被剥掉，别处写 `[[tscl="fact:ver"]]` 展开同一个值）。这种句内定义**必须单行闭合**。
- 宏体**跨行**时不要内联进表格单元格；定义本身也别写进表格行（`|` 会破格）。
- 要核一个值，`kb_read target=<定义 id>` 直接回定义体、定义处、被谁引用。
- 定义块内部的 `##` **不会**变成节点——它只是文本。

## TID 规则

- 文件节点：`<目录>:<文件名 slug>`，例如 `doc/03-工程经验与坑.md` → `doc:03-工程经验与坑`
- 显式节点：`<node name="abi">` 里的 `name` 原样就是 TID，可跨文件引用（`tid="…"` 等价，`title="…"` 可另给显示名）。TID 不要求含冒号。
  - 属性缺省：`title` 缺省 = `name`（H1 只决定**文件节点**的标题，不进任何节点正文）；`type` 缺省取所在目录名（`doc`/`lessons`…）；`parent` 缺省 = **本文件第一个 `<node>` 的 name**，文件里还没有别的 `<node>` 时才是文件 TID——所以同一个文件里第二条 `<node>` 会挂到第一条下面，要并列就显式写 `parent="<文件TID>"`
  - 库根直接放的文件（如 `README.md`、`README_EN.md`）TID **没有目录前缀**，就是 `readme`；但它的是**文件节点**，`kb_write` 只能用「路径 + replace」改整篇，写 `target=readme` 会被拒绝
- 手写 `<node>` 时开闭标签各占一行；缺 `name`/`tid` 的块会整段退回正文并在 diag 里 warning，不会静默丢失
- 读的时候允许前缀兜底：`kb_read target=doc:02` 能命中 `doc:02-运行环境`（按 slug 前缀匹配，唯一才命中；多个候选会报 `未找到节点 … 候选:`）；但**写引用仍要写全 TID**
- 代码区（` / ~~~ ` 围栏与行内代码）里的 `[[…]]` / `<node>` / `<tscl>` 是示例，不解析、不计引用、也不跟着改名——两种围栏同等对待（闭围栏要同字符且不短于开围栏）。讲语法时直接写在代码里即可。
- 段节点：`## 3.1 xxx` → `<文件TID>:3.1`，是**位置型**的：插一节就漂。链接它只是 warning（指错了跳错节），但**别拿它当需要长期稳定的锚点**——要稳定就写显式节点。
- 改名走 `kb_rename`，它会重写全库引用。`new_name` **只能是同目录的文件名**：带目录分隔符或 `..` 会被拒；跨目录搬文件先手工 `git mv` 再跑 `kb_rename` 修引用。新名字 slug 化后若撞上已有 TID（`03 a` 与 `03-a` 是同一个）也会被拒。改名有 error 时回执会写明，退出码 2。

## 写

```
kb_write target=lessons/003-cp936.md  mode=create  content=...
kb_write target=<显式节点TID>          mode=node    content=...   # 只换 <node> 之间的正文
kb_write target=<段节点TID>            mode=node    content=...   # 也可以换 ## 段落的正文
kb_write target=doc/03-...md          mode=append  content=...
```

- 写完**看返回值里的校验结果**：悬空引用、重复定义、`<node>` 没独占一行，都会当场报回来。
- 改已有内容用 `append` / `node`，不要 `replace` 整篇（会丢掉别人刚写的段落）。
- 新建文件前先 `kb_read mode=toc` 确认没有同主题的旧文件。
- 库是内嵌 git 仓库，**写入/改名成功后会自动快照**：commit message 形如 `autosnap: 3 处变更`，回执里有一行 `快照: autosnap: 3 处变更`。**写后自检有 error 时不再快照**，修好后的下一次写入会一并提交。看历史用 `kb_vcs_status`（默认最近 5 条，`count` 可调）。不想要快照就配 `git: false`——建库、写入、改名都会跳过。
- 段节点一旦写过 `<node>`/`<tscl>` 标签，或段内还有更深的标题（`###`…），这段就**不能再用 `mode=node` 改**（工具会拒绝），改走「路径 + `mode=replace`」，或者先 `kb_read` 出来整段重写。围栏（`/ ~~~`）里的标签与 `#` 是示例，不算数——写「教怎么用 nodekb」的段落可以放心放代码块。
- `mode=node` 的 `content` 里**不要带标题行**：首行若恰好是本段标题会被自动剥掉（`kb_read` 渲染出来就带标题，直接贴回去是常见操作）；其余任何 `#`/`##`/`###` 标题行都会被拒绝——段正文里插标题会新开一个段、把本段静默劈成两半，要加子节请用路径 + `replace` 整篇重写。
- 段边界只认围栏外、`#`/`##`（及更深）的标题行；文件原本用 CRLF 就继续用 CRLF（不会被写成混排）。
- `kb_write` 的 `target` 判定顺序：**库里已有的 TID**（含没有冒号的）→ 库根文件名 → 像路径的字符串（补 `.md`）。三者都不是就报「没有名为 … 的文件或节点」。
- `content` 里**不要写 `</node>`**：它是包在本节点外面的结构，写进正文会把节点提前截断（后面的内容掉到节点外）；工具会直接拒。`<node>` / `<tscl>` 开标签要求成对，未闭合会吞掉后面的节点/段，同样被拒。两种合法写法照旧：单行 `<node name="x">正文</node>`、以及「行首定义 + 同行后缀」的 `<tscl id="v">1</tscl>` 后面带说明，整篇 `mode=replace` 不受成对检查限制。
- 写进去的坏结构（手改、git 合并、`replace` 逃生口）由**解析器收尾兜底**：未闭合的 `<node>` / `<tscl>` 现在会让 `kb_diag` 报 **error**。
- `content` 里的 CRLF 会被归一成 LF、落盘时再按原文件的换行写回——从 CRLF 文件抄一段回来不会写出 `\r\r\n`；`append` 的结尾换行由工具补，CRLF 文件里不会混进裸 `LF`。
- 路径必须是**小写 `.md`**，且不能有点开头的目录/文件（解析器会跳过）。回执里的路径统一 `/` 分隔；段写入会自动补「标题 / 空行 / 正文 / 空行」，且**幂等**——同一段连写多次不会每次多长一个空行。

## 注意事项

0. 库定位找不到时先 `kb_list`：它会写明本会话判定的工作区、来源（会话头 / 配置 / 面板）与每个库的绝对路径。已有的库用 `kb_register dir=<库目录> name=<名字>` 登记进项目的 `kb_registry.json`，不要让人去改插件配置。插件升级后第一次跑 `kb_diag`，报告里会多出一条 `plugin-updated`：提醒「规则变了，先重读本技能」。每条库只提醒一次（记在 `.nodekb/.plugin-state.json`，位置在 `.git/info/exclude` 里——诊断不会把库弄成「有未提交改动」）。
1. 不要把整段对话贴进 `doc/` —— 记的是过程，不是结论。
2. 不要把同一件事在 `doc/` 和 `lessons/` 各写一份 —— 抽成 `<tscl>` 定义，两处都引用它。

## 实现细节（只在代码里，踩到了再回来看）

- 一次渲染里宏展开上限 **64 次**（病态循环引用会直接报错，而不是把上下文撑爆）。
- 读一支子树时会**渲染两遍**：第一遍收集这一支里哪些定义被展开过，第二遍把同支内的定义块抹掉——所以定义和它的引用在同一支里时，值只出现一次。
- `kb_diag` 的 `advice` 一次最多 5 条；「同一句散在多处」只报最扎眼的 2 条。
- `kb_rename` 会重写 `[[…]]` 引用**和** `<node>` 的 `tid=` / `name=` / `parent=` 属性（`parent` 漏改子节点会立刻变孤儿，`diag` 直接 errors）；单双引号都认，围栏里的示例不动；属性在 `<node>` 开标签上跨行书写时不会被改（只改单行内的那份）。改名后若还有节点 TID 前缀指向已不存在的旧文件，`kb_diag` 会 warning「TID 前缀指向不存在的节点」。
- 围栏判定全库只此一份（`lib/engine/parse.js` 的 `makeFenceTracker`）：解析、段写入、改名、advice、`validateContent`、`diag` 都调它。`~~~` 与 ``` 同等，闭围栏必须同字符且不短于开围栏。
- 宿主侧的写端点 `/nodekb/api/rename` **只收同源 POST**（GET 返回 405、跨源 403、body 解析失败 400；`dry_run:true` 只报会改哪些引用），`/nodekb/api/client-report` 收 POST、GET 是读自证状态。
- 写入的校验分两层：`validateContent`（标签形态 + 成对，`mode=replace` 关掉成对那半）+ `writeInto` 入口的换行归一与路径检查；改名除了重写引用，收尾也跑一次 `diag` 把 error 带进回执。**改名同样先自检、再快照**（坏结构不进 git 历史，和 `kb_write` 一致）。撞名报错给的是库内相对路径，不是绝对路径。
