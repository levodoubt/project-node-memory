# 1.5.18

「插件升级后的一次性提醒」（`plugin-updated`）有四处边界不对，都是小修，不改任何既有行为。

## 修了什么

1. **命令行不吃 `advice.limit`**：1.5.16 起两层都出这条提醒，但工具层 `kb_diag` 会按 `advice.limit`（缺省 `maxItems` = 5）截断，命令行只 `unshift`——同一个库，两条入口条数不同。现在两边共用 `lib/engine/notice.js` 的 `withNotice(advice, notice, opts)`。
2. **带 BOM 的状态文件被当成「1.5.0 之前」**：`.nodekb/.plugin-state.json` 若被 PowerShell 之类写过（带 BOM），`JSON.parse` 直接抛，于是把「1.5.17 建的库」说成「1.5.0 之前」。现在先剥 BOM 再解析（与 `engine/config.js` 读 index 的做法一致）。
3. **状态写不进去时无声重复**：只读库、权限不足时 `markSeen` 失败但异常被吞，每次 diag 都报同一句，看的人分不清「又升级了」还是「压根没存上」。现在 `markSeen` 返回布尔，失败时回执追加「（状态文件写不进去，下次还会提醒）」。
4. **口径写明**：这条提醒不受 `advice: { display: false }` 控制（那个开关只关改进建议），但计入 `advice.limit` / `maxItems`。
