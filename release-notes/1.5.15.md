# 1.5.15

把 1.5.13 / 1.5.14 实测出来的七个「明明能用却不顺手」的地方收掉：库名在两套接口里不一致、advice 只能干看着、目录视图一次吐太多、段写入不认标题、举例被当错链接。

## 库名统一

- 插件启动时把生效配置（`registries` / `libraries` / `workspace` / `exclude` / `advice`）抄到 `~/.dsh/nodekb/config.json`；`nodekb` 命令行据此解析名字。
- 于是「工具层 `kb="filmmeasure"` 能用、命令行 `--kb filmmeasure` 报未注册」这种两套名字的事不会再有。`config.libraries` 里写技能目录或 `.nodekb` 本身都能定位。

## advice：能看见，也能管

- `advice: { display: false }` 整块关掉——有的库结构刻意松散，看建议只会分心。
- `advice: { limit: 10 }` 控条数，`0` = 全部给出（显式给 `limit` 就以它为准）；`advice: { maxItems: 10 }` 改默认上限。
- `diag_ignore.json` 新增第四组 `advice: [{code, tid}]` 逐条豁免（两者都是正则、同时命中才压掉）。
- `nodekb diag` 以前恒为 0 条 advice、且不吃配置阈值；现在与工具层走同一份配置、同一套阈值。

## 目录视图默认折叠

- `kb_read mode=toc` 默认只展开两层（`depth` 可调，`0` = 只列目标节点），大库不再一次吐上千 token。
- 想看全量仍可以显式放大 `depth`。

## 段写入认标题

- 首行是**同级或更浅**的标题 → 连标题一起换：改段名、降级不必整篇 `replace`。
- 首行**恰好是本段标题** → 剥掉（`kb_read` 渲染出来带标题，直接贴回去是常见操作）。
- 首行**更深**、或正文中间还有标题行 → 仍然拒绝：段正文里插标题会把本段劈成两半。

## 举例不再被当成错链接

- 悬空引用的报错直接说清两种可能：TID 写错了，或者这里只是举例——举例请用反引号包起来。
- 同一处不会再被「不可解析的 TID 文本」重复报一遍（`[[…]]` 真引用本来就不查）。

## Windows 管道之外的出口

- `nodekb … --json --out 结果.json`：中文 JSON 不经过 PowerShell 管道（PS 按 CP936 收 node 的 UTF-8，`| ConvertFrom-Json` 直接 `ArgumentException`）。文件是干净 UTF-8、不带 BOM。

## 自检

- `node scripts/check.mjs` → 604 项全绿；`node test/parity.mjs` → 18/18（Python 参考实现的 `toc_lines` 与悬空引用文案同步更新）。

## 已知未改

- 结构手术（拆节/合并文件）仍没有一键命令，只做了 `rename --batch` 这一类。
