# 1.5.9

读路径补三件「本该有但一直没有」的事：**大节点分窗读**、**只要命中行**、**超限不报错而是续读**。
默认行为不变——不传新参数就是 1.5.8 的输出。

## 主体太长就只能整段吃，或者放弃

`kb_read` 只有 `maxlen`（超了直接报错），没有 `offset` / `limit`。一个 17k 字符的段节点，Agent 要么整段读进上下文（≈5000 token），要么放弃。
`read` 工具有行窗，`kb_read` 没有——这是读路径上唯一的硬墙。

- `lib/engine/mdlib.js`：解析时给每个节点记一份**行号表** `lines`（与 `content` 逐行对齐，trim 时同步裁剪）。
  正文里已经去掉了 H1 与 `<node>` 标签行，行号不能靠数 `content` 得到，必须解析时记。
- `lib/engine/render.js`：新增 `node_window()` / `render_node_window()`——先切行再展开，宏只在窗口内展开。
- `lib/host/tools.js` + `lib/engine/commands.js`：`kb_read` 新增 `offset` / `limit`；`mode=node` 按**本节点正文行**，
  `mode=subtree` 按**渲染结果行**。返回头写明两种坐标：
  `[doc/03-x.md#L120-L179 · 本节点第 41–100 行 / 共 320 行]`。
- `lib/engine/commands.js`：新增 `clipText()`，按行边界裁，返回 `take`（给到第几行）供续读。

## 超 `maxlen` 报错 → 截断 + 续读坐标

以前 `mode=subtree` 超限是 `渲染超上限: N 字符 > maxlen`，整次调用失败，调用方只能传 `maxlen=0` 赌一把。

- 现在截断到行边界，结尾给 `（后面还有 N 行，继续用 offset=X）`；`maxlen=0` 仍可强取全量。
- 等价改动也落在 `cmdRead`（`lib/engine/commands.js`）；`test/parity.mjs` 里这一项**有意分叉**（Python 参考实现仍报错），
  改为只断言 JS 的新契约。

## 「这个词在哪一行」不必读整段

- `kb_read find=关键词`：返回命中行（`文件#L行号 · TID  行文本`，最多 20 处），不返回正文；拿到行号再用 `offset` 读那一段。
  `mode=node` 只查本节点，其余查整支。
- `kb_search lines=true`：每个命中节点再给 ≤3 条行级命中（`文件#L行号  行文本`），默认关闭。
- 行号是**同一次解析快照内的临时坐标**，只用来喂 `offset`；文档里的引用仍用 TID。这点写进了 SKILL。

## 顺手修掉的一处 O(N²)

`children()` 每次调用都扫全表，`toc` 一棵 N 节点的树就是 O(N²)（25 MB 的实测库 toc 要 153 s）。

- `lib/engine/render.js`：加父→子索引缓存（`WeakMap`，按 `nodes.size` 失效，热重载后自动重建）。

## 对拍脚本会把整个源码仓库提交掉

`test/parity.mjs` 的夹具库放在 `test/fixtures/sample/.nodekb`，而 Python 参考实现在**每次解析库后**都尝试自动快照
（read / search / diag 都算），且没有 JS 这边「库目录必须自己就是仓库根」的护栏——它 `git add -A` 时顺手把
源码仓库里所有未提交的改动一起提交成 `autosnap: N 处变更`（1.5.8、1.5.9 期间各踩一次，都是发版前发现）。

- `test/parity.mjs`：夹具先整份复制到系统临时目录再对拍，进程退出时删掉；`--lib` 指向那份拷贝。
  Python 侧再怎么写 git 都碰不到源码。
- `scripts/check.mjs`：加一条源码断言（对拍脚本必须 `mkdtempSync` 并且 `FIX` 指向临时目录）。
