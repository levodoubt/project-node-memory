# 1.5.1

1.5.0 实测反馈的收尾：四处「功能在、但最该生效的场景里不生效」的缺陷，以及文档与实现对不上的地方。

## 修掉的缺陷

- **缺 H1 检测复活**：文件节点的 `source` 是绝对路径，之前又拼了一次库根，`readFileSync` 每次都抛错被吞掉，`advice` 里 `missing-h1` 从来没出现过。
- **旧库也能收到更新提醒**：1.5.0 之前建的库没有状态文件，之前直接 `return null`，恰好漏掉了它最该管的那些库；现在「没有状态文件」按旧库处理，提醒一次。新库仍不受打扰（`kb_init` 直接记为当前版本）。
- **`git: false` 真的关得掉**：之前只在 `kb_init` 判断，`kb_write` / `kb_rename` 里的自动快照照旧发生。
- **改名会连 `<node tid="…">` 一起改**：之前只重写 `[[…]]` 引用，文件 TID 变了、嵌套节点还叫旧名，`kb_diag` 也看不出来；现在 `tid=` / `name=` 属性一起改写。另外 `kb_diag` 新增一条 warning：「TID 前缀指向不存在的节点」（只在上一级确实是本库目录节点时提醒，自定义 `fact:…` 不会误报）。

## 变清楚的地方

- `kb_vcs_status` 名实相符：真的返回最近 N 条快照（`count`，默认 5），不再只报最后一条。
- `kb_write` 的参数说明写明 `mode=node` 支持 `##` 段、以及「段内已有标签时会被拒绝、改走 `mode=replace`」。
- 技能补齐只在代码里的事实：`<node>` 的 `title`/`type`/`parent` 缺省链、库根文件的 TID 没有目录前缀、前缀兜底的歧义行为、`MAX_EMBED=64`、整支渲染的两遍处理、`advice` 每次最多 5 条、`diag_ignore.json` 的用法、快照的 commit 文案。
