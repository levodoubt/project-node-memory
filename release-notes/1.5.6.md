# 1.5.6

1.5.5 修掉了「写成功但库被写坏」，这一轮又发现 **新代码自己引入的两处**（校验误拒、空行累积）
和一处 **诊断盲区**（坏结构进库了但 diag 一个字不报）。自检 **452 项**（新增第 15 组回归）。

## 校验误拒合法写法

`validateContent` 的 tscl 成对判定只统计「行首 `<tscl`」与「行尾 `</tscl>`」，于是
`<tscl id="v">1</tscl> 后面带说明`（解析器完全支持）被判成未闭合、整次写入被拒。
单行的 `<node name="x">正文</node>` 也被「必须独占一行」挡掉，而解析器与 `mode=node` 都能就地改写它。

修法：校验器改成和解析器**同一套状态机**——行首 `<tscl` 开定义体，定义体内只有独占一行的
`</tscl>` 才算闭合，同行后缀算正常；单行 `<node…>…</node>` 直接放行。真正未闭合的仍然拒。

## 段写入每次多长一个空行

`writeSection` 用 `bodyEnd`（退到段尾空行之前）做替换终点，`body` 又固定补一个尾部空行 →
旧空行既不消费也不复写，于是每写一次多一个空行（`\n\n`→`\n\n\n`→4 个…），段尾到文件末尾同理。
段是最高频的写入形态，长期迭代的文档会越来越松散。

修法：替换区间改用**未 trim 的 `end`**，新正文自己带「前空行 + 后空行」，长度固定 → 幂等。

## 诊断盲区：未闭合的 `<node>` / `<tscl>` 零告警

写入侧堵住之后，手改 / `git merge` / `mode=replace` 逃生口进来的坏结构仍然没人管：
`<node name="abi">` 没闭合 → `abi` 把后面的 `## 2. …` 整个吞进正文，段节点直接不存在；
`<tscl>` 没闭合 → 文件后半段全被当定义体。两种都是 `diag: 0 error / 0 warning`。

修法：解析器收尾两句兜底，`stack` 非空 / `tscl_open` 仍为真就报一条 **error**
（内容是**真的丢了**，不是「疑似漂移」，所以不降级成 warning）。

## 其余四条

- 「嵌套开标签」检查也犯了同一类错：它拿**原始正文**跑正则，于是文档里用行内代码提到标签
  （`` `<tscl>` / `<node>` ``）会被当成嵌套开标签报错。现在先把代码区段（围栏块与行内代码）抹成空格再判断，
  真的嵌套仍然报。**写文档讲语法不该被自己的诊断拦住**。
- 大写扩展名的报错提示自相矛盾（引号里贴回的还是刚被拒的 `notes/x.MD`）：现在给出可用名字 `notes/x.md`。
- `kb_rename` 撞名报错给绝对路径：改回库内相对路径（与 1.5.2 定的口径一致）。
- `kb_rename` 先快照后自检：结构写坏的那一版会进 git 历史。现在和 `kb_write` 一致——**先自检，`errs === 0` 才快照**。
