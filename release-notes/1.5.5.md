# 1.5.5

1.5.4 之后又一轮实测审计：六类问题都确认修好，但发现 **3 个「写成功、库却被写坏且无提示」** 的缺陷

## 必修

### content 自带 CRLF → 文件被写成 `\r\r\n`

`write.js` 的 node / 段两条路径都用 `split('\n')` 拆内容，`\r` 留在行尾，再 `join(eol)` 拼回去；
CRLF 文件里 `eol='\r\n'`，于是每行变成 `…\r\r\n`。回执报成功、`kb_diag` 也不报错，字节却已经坏了
（模型从 CRLF 文件抄一段内容回来写就必踩）。

修法：`writeInto` 入口一次性把 content 归一成 LF（`replace(/\r\n?/g, '\n')`），落盘时再按原文件的换行拼。

### content 里的 `</node>` / 未闭合 `<node>` 被放行 → 节点被截断且 diag 不报错

`validateContent` 只查「`<node …>` 独占一行 + name 合法」，单行 `</node>` 也算合法形态，
但它其实是**包在本节点外面**的结构：写进正文会把节点提前截断，后面的内容掉到节点外，
库看起来「写成功了」，多出来的只是一个孤立标签 warning。未闭合的 `<node name="x">` 更狠——
它让本节点的正文变成后面那一整段，段节点直接从库里消失，而 diag 是 0 error / 0 warning。

修法：`validateContent(text, where, { balance })` 统计围栏外的 `<node>` / `</node>` /
`<tscl>` / `</tscl>`：`</node>` 多于 `<node>`、开标签未闭合、tscl 不成对，一律拒绝并给逃生口
（路径 + `mode=replace`）。`mode=replace` 传 `balance:false` —— 整篇重写是作者说了算。

### `kb_rename` 不查新 TID 是否被占用 → 重复 TID、文件从库里消失

只查了 `fs.existsSync(to)`，没查 `nodes.has(newTid)`。Windows 上极常见：已有 `doc/03-a.md`，
把 `doc/zz.md` 改名成 `03 a`（slug 后同为 `03-a`）——目标文件不存在、检查通过，改完两个文件
映射到同一个 TID，解析器把后一个当「已跳过」，**整份内容再也读不到**，回执还是一句干净的
「已重命名…更新了 1 处引用」（`kb_rename` 原本不跑 diag，`kb_write` 跑）。

修法：`rename.js` 在算出 `newTid` 后查 `nodes.get(newTid)`，被别的节点占用就报出占用者路径并要求换名；
`kb_rename` 收尾补一次 `diag`，回执里带上 error / warning，退出码 2。

## 同一类「成功但库看不见」，一并堵掉

- `target` 落在点目录或大写扩展名（`.draft/x.md`、`notes/x.MD`）：写入成功、解析器永远跳过。
  现在路径必须是小写 `.md`，且任何一段以 `.` 开头直接拒。
- `append` 的 content 自带 `\n` 结尾 → CRLF 文件里混进 1 个裸 LF。现在由工具剥掉结尾换行、
  统一补一个文件的 eol；内容只有空白则拒绝。
- 回执相对路径分隔符不统一：append/replace/create 以前给 `doc\01-a.md`，node/段模式给 `doc/01-a.md`。
  现在统一 `/`。
- 段写入后标题与正文之间没有空行（纯排版）：现在自动补「标题 / 空行 / 正文 / 空行」。
