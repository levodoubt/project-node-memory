# 1.5.16

三处「用起来还是不够顺」，都来自同一份实测反馈：目录看不出该不该点进去、`find` 词序一变就找不到、命令行与工具层的诊断输出不同构。

## 目录报「整支」字符量

`kb_read mode=toc` 每节点原来只有自己的字符数。目录节点（`doc/`、`lessons/` 这类）自身正文是 0，于是目录里一行行全是「0 字符」，读者反而看不出底下有多少东西。

- 有子节的节点头部多报一段：`· 整支 N 字符`（自身 + 全部后代之和）；叶子节点保持原样，不硬加。
- `subtreeChars()` 在 `lib/engine/render.js` 里，Python 参考实现 `kb/render.py` 同步加了 `subtree_chars()`。
- 对拍（`test/parity.mjs`）比较 toc 结构时抹掉这一项：子节集合本身受 1.5.8 起的「缺省 parent 按结构」分叉影响，整支量由 `scripts/check.mjs` 单独断言。

## `find` 多词退让

`kb_read find="Fresnel coefficient"` 以前是纯子串匹配，文档里写的是 `Fresnel reflection coefficient`，于是零命中——而零命中在语义上又说不出「是真的没有」还是「词序/词形不同」。

- 整串没中时按空白/逗号/顿号切词（每词 ≥2 字符），**每个词都要出现、不限顺序**，取交集；退让命中时回执写明「整串没中，改成『每个词都要出现』的退让匹配：Fresnel + coefficient」，并保留用户原本的大小写。
- 退让后仍为空才报「未命中」，所以「零命中」依旧意味着真的没有。
- 只退让不退化成模糊搜索：不做编辑距离、不做同义词。

## 命令行与工具层同构

- `plugin-updated` 这条一次性提醒（插件版本变了、这个库还没按新版本体检过）以前只长在 `lib/host/tools.js` 里，于是 `kb_diag` 有、`nodekb diag` 没有。现在搬到 `lib/engine/notice.js`，两边共用；`lib/host/tools.js` 原样重新导出，对外接口不变。
- `nodekb … --out 结果.json` 按后缀自动当 `--json`，不必把同一个意图写两遍（散文输出想落文件就写 `--out 结果.txt`）。
