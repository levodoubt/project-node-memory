# 1.5.3

修 1.5.1 新增的「`##` 段直接改写」在真实文件上会破坏内容的三个问题，外加两处自相矛盾。

## `mode=node` 段写入：围栏感知

- **段边界只认围栏外的 `#`/`##`**。旧实现按行首是否为 `#` 判断段结束，于是代码块里的 `# 这是注释` 被当成下一段开头：围栏开头连同那行被替换掉，`echo hi` 与新正文错位，回执却报了一个看似正常的行区间。现在按 `line.trim().startsWith('```'/'~~~')` 翻转 `fenced` 状态（与 mdlib 同一写法），围栏内的行不参与边界判断。
- **「段内有 `<node>`/`<tscl>` 就拒绝」同样跳过围栏**。此前只要段里放一段书写示例就会被拒——而「教怎么用 nodekb」的段恰好都是这种。围栏里的标签算示例，不算结构。
- **`<node>` 块的闭合扫描也跳过围栏**：正文里示例的 `</node>` 不再被当成真闭合（否则会从示例处截断、尾部残留 `</node>`）。

## 换行不再混排

段写入、`<node>` 块写入、`append` 三处都改为「读原文件 EOL → 拆行 → 用同一 EOL 拼回」。CRLF 文件以前会被塞进 LF 行，同一个文件出现 `\r\n`/`\n` 混排。

## 两处自相矛盾

- **`advice` 条数**：`plugin-updated` 在 `computeAdvice` 截断之后才 `unshift`，一次可能返回 `maxItems + 1` 条。改成先拼、再统一截断。
- **`kb_diag` 会弄脏库**：状态文件原先靠「往 `.gitignore` 追加一行」来忽略，而 `.gitignore` 是被跟踪文件——升级后第一次诊断就把库变成「有未提交改动」，直到下次 `kb_write` 才被 autosnap 顺手提交。现在写 `.git/info/exclude`（工作树的 `.git` 文件也认），诊断不再改动工作树。

## 快照顺序：先自检，后快照

`kb_write` 原先先 autosnap 再自检，于是结构写坏的那一版也会进历史。现在自检有 error 就不快照，回执写「未快照：写后自检有 error，修好后的下一次写入会一并快照」。回滚目标始终是上一个好状态。

## 文档

- README / README_EN：自检条目不再写死项数（结尾会打印 `N passed`），配置表补上 `git` 与 `advice`（`minFragNodes` / `fragChars` / `longSection` / `maxItems`）。
- 技能：写明围栏里的标签是示例、段边界只认围栏外的 `#`、CRLF 保持不变、自检失败不快照、状态文件在 `.git/info/exclude`。
