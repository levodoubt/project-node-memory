# 1.5.7

这一版全在修「库自己推荐的写法，被自己的工具误判或误伤」——碎片判据、小节父指针、写入校验、检索片段。

## 碎片文件的判据改成看整篇

`merge-fragments` 以前只数**文件节点自身的正文**（H1 到第一个 `##` 之间的那句导语）。于是「一文件一章节、正文全在 `##` 下」这种正是插件推荐的组织方式，必然被判成「单节点小文件」：一个 21 个 1KB 文件、结构完全健康的库，报「10 个单节点小文件（每个 < 500 字符）」。

现在按**整篇**算：文件节点正文 + 它下面全部 `##` 段与 `<node>` 的总字数。文案同步改成「整篇不足 500 字符」。

## 小节的父节点恒为文件节点

以前 `## 3.1` 的 parent 取「本文件第一个显式 `<node>`」，于是「按 `##` 组织 + 一堆具名锚点」的文件，TOC 会串成 `3.1 → lesson1 → [3.2, lesson2, 3.3 …]`；给每个 `<node>` 补 `parent="<文件TID>"` 反而让 19 个小节全堆到某个 lesson 底下。

现在小节一律挂文件节点：两种组织方式在同一个文件里并存时，TOC 里是并列的。显式 `<node>` 的 `parent` 缺省行为不变（仍是本文件第一条 `<node>`，要并列就显式写）。

## 写入校验与解析器同一口径

- 行内代码里的 `<node>` / `<tscl>` 是示例，不再被拦——正文里讲语法可以直接写 `` `<node name="x">` ``。
- 报错行号按你传的 `content` 算（首尾空行不计）。以前 `content` 开头多一个换行，报错就整体偏一行，只能靠猜。

## 检索片段嵌出 `<tscl>` 的值

`kb_search` 的片段以前会把 `[[tscl="fact:limit"]]` 原样抛出来，搜到值还要再读一次定义；现在片段走同一次渲染，值就在片段里。

## 其余小摩擦

- `long-section` 的 `fix` 补一句：拆节会重排位置型 TID（`文件:2.1` 这类），已有链接会漂；要稳定锚点就配显式 `<node>`，或提到独立文件、原节留一行指针。
- `kb_init` 的 `dir` 误传上级目录时直接拒（目录里已有 `README.md` / `doc/` 就报「库目录本身，不是上级目录」），不再把 `README.md`、`doc/`、`index/` 散进项目根。
- `kb_list` 不再让「路径已不存在」的登记占版面：只在末尾报一行总数，删对应 `kb_registry.json` 项即可。
