# project-node-memory 1.3.3

npm: https://www.npmjs.com/package/project-node-memory/v/1.3.3

从这一版起，**版本变更只记在这里（Release 页），README 只描述当前版本**。

## 本版变化

- **README 改为只描述当前版本**，并移除两处历史内容：「从 1.0 升到 1.1」整节（搬到下面）与英文版的
  「Renamed from `dsh-nodekb` at 0.2.0」。
- 工具数对齐为 **9**（README 标题此前误写「10 个工具」）；示例里的 `fact` 写法从 `<node>` 改为 `<tscl>`，
  与当前语义一致。
- 工具描述与系统提示词改为平实的契约式表述（1.3.1）：去掉「比 read 好」「比 grep 省往返」这类劝告，
  只保留参数语义、使用时机与失败后的出路。工具描述总长 3,391 → 3,117 字符，提示词段落 820 → 604 字符。
- `kb_read` 的 `target` 参数说明补回「（回定义体、定义处、被谁引用）」（1.3.2）。

## 从 1.0 升级

数据格式没变——md 还是 md，TID 还是那些 TID，插件卸了照样能读。变化只有两条：

1. **`[[x]]` 现在只出链接**，不再把被引用节点的正文复制进来（要复制原文请显式写 `<tscl>`）。
   好处是引用不再撑大渲染结果，位置型小节 `## 3.1` 也能点了。
2. **`kb_init` 不再建 `facts/`**。已有的 `facts/` 不会被动，`kb_read` / `kb_search` 照常；只是新库默认只有
   `doc/ lessons/ todo/ index/`，事实改写成 `<tscl>` 定义放进它所属的 `doc/` 里。

老库要不要迁？**不迁也能用**，只是 `kb_diag` 会给每条裸引用一条 warning。要迁就按 `kb_diag` 的清单逐条改成
`[[node="…"]]` / `[[tscl="…"]]`（只改写法，不动 TID 与文件）。
