# 1.5.17

五条反馈里，四条指向同一类病：**同一件事有两份实现，或者只能靠忍着**。这版把「退让」收成一份、把「确认过就别再报」给成一条通道，并让「我到底有哪些库」重新可见。

## `find` 只有一份实现

宿主 `kb_read` 的 `find` 以前直接调 `findLines`，只有整串子串匹配；而工具描述里写着「整串没中会按词退让」——那是引擎 `cmdRead` 里的另一份实现。于是同一个词，命令行找得到、工具层找不到。

- 新增 `lib/engine/search.js` 的 `findWithFallback(nodes, tid, term, {deep, max, libRoot})` → `{hits, used, loose}`：先整串，零命中时按空白/逗号/顿号切词（每词 ≥2 字符），每个词都出现、不限顺序，取交集。
- `lib/engine/commands.js` 的 `cmdRead` 与 `lib/host/tools.js` 的 `kb_read` 都改调它，删除引擎里那份内联退让。
- 行为不变：退让后仍为空才算未命中；不做编辑距离、不做同义词。

## `example-tscl`：示例被写成了定义

`<tscl …>` 出现在行首就是真定义。贴示例时忘了包围栏，后面几十行章节会被一路吞进定义体，而 1.5.16 及以前只在「嵌套开标签」时才报错，看不出「你这多半是示例」。

- 新增 advice `example-tscl`：定义体里出现围栏外的 `## ` 标题行或 `<node>` 标签就提示，点名是 `##` 还是 `<node>` 被吃、有多少字符，最多列两条最大的。
- `fix` 给出三条出路：放进 ``` 围栏、改成行内写法、或把值收成一句话让 `</tscl>` 紧跟其后。

## `diag_ignore.json` 第五组：`warnings`

`blocks` / `lines` 只作用于「内容重复」那一类，别的 warning 想「这条我确认过」只能看它一直挂着。

- 新增 `warnings: [正则…]`，匹配的是**告警文案本身**（如 `^不可解析的 TID 文本`），一条命中就把那条从报告里拿掉。
- 与 `tids` 的分工：`tids` 匹配 token（只压两条 TID 相关告警），`warnings` 匹配整条文案（更粗，能不用就不用）。
- 豁免之后 `exit_code` 与 `status` 都按过滤后的 warnings 算：`--strict` 不再因为「你确认过的那条」失败。
- 「内容重复」「节点内重复行」两条报错顺带提示这条通道。

## 跨项目的库重新可见

`kb_list` 只报本工作区发现的库之后，用过的别处库（comfyui、minecraft…）从列表里消失了——按名字调可能还在，但「我手头到底有哪些库」的记忆没了。

- `lib/engine/config.js` 新增 `rememberLibrary()` / `knownLibraryIndex()`，索引落在 `~/.dsh/nodekb/index.json`（上限 200 条，按最近使用排序）。
- `openLibrary`（宿主）与 CLI 的 `openTarget` 打开库时顺手记一笔；`kb_list` 与 `nodekb list` 末尾提醒「另有 N 个库不在本工作区」（附前 5 个名字与目录）。
- 索引**不参与解析**：那些库仍然要传路径才能用；夹具/`node_modules`/`.tmp-*` 里的库不记，免得自检把测试库写进所有人的列表。
