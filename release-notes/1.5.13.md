## 改名

- **只改大小写可以用 `kb_rename` 了**：`031-T7代理.md → 031-t7代理.md`。以前 Windows / macOS 上 `existsSync(to)` 命中的是文件自己，报「目标已存在」；现在识别出「只差大小写」直接走一次中转改名，TID 本来就是小写的、引用不需要动。回执会写「只改了大小写，TID 仍是 …」。
- `nodekb rename --batch 计划.json`：批量改名，计划是 `[{target,new_name}]` 或 `{"renames":[…]}`。逐条执行、每条都重新读库（前一条改过的引用就是后一条的输入），**中途失败立刻停**并在回执里列出「停在第几条 / 前面哪几条已落盘」。`--dry-run` 只演练不落盘。

## 库自己的规矩：`.nodekb/rules.json`

每个项目对库都有一套「我们这儿这么写」的约定——以前只能写在各自 README 里靠人守，或者项目自己写脚本 gate。现在可以声明，`kb_diag` 照着查：

```json
{
  "refStyle": { "default": "plain", "doc": "expand", "lessons": "expand" },
  "limits": { "bytes": { "default": 12288, "lessons": 4096 } }
}
```

- `refStyle` 的目录键是文件相对库根的第一段目录（库根散文件用 `.`）；`expand` = 允许 `[[node="…"]]` 且 `[[tscl="…"]]` 只能指向 `fact:` 开头的定义；`plain` = 不许写 `[[…]]`，改写成反引号纯文本。
- `limits.bytes` = 单文件体积上限；超了报 warning。
- 围栏示例与行内代码不算违规；违规带库内相对路径与文件行号；`rules.json` 写坏只报一条 warning，不影响读库。
- 不声明就没有任何新告警（默认零配置、零行为变化）。
