# 1.5.12

按「Agent 不该为了维护工具而再写工具」这一条，把本机六套自制脚本里反复出现的四类缺口收回插件。

## 新增：`nodekb` 命令行

`bin/nodekb.mjs` + `lib/cli.js`，与工具层共用同一份 `lib/engine/*`。

```
nodekb list [--all] [--json]
nodekb read <TID|定义id> [--node|--toc|--raw] [--offset N] [--limit N] [--find 词] [--json]
nodekb search <查询> [--type doc] [--limit N] [--lines] [--json]
nodekb backlinks <TID|定义id> [--json]
nodekb diag [--strict] [--json]
nodekb write <TID|相对路径> [--mode node|append|replace|create] [--content|--file|--stdin]
nodekb rename <目标> <新文件名> [--dry-run]
nodekb vcs [status|log] [--count N]
```

- 库定位 `--kb <库名|库目录|任意目录>`；命令行里显式给路径即授权，不受工具层的工作区白名单限制。
- 读命令退出码：`0` 成功 / `1` 无命中 / `2` 参数错或自检有 error（与 `kb_diag` 一致）。

## 新增：稳定引用面

- `package.json` 加 `bin`（`nodekb`）与 `exports`：`./engine`（`lib/engine/mdlib.js`）、`./engine/*`、`./cli`；`files` 增收 `bin`。
- 以前项目要 import 引擎只能硬编码 `file:///D:/…/lib/engine/*.js`（本机五个库都这么干过），现在走包路径即可。

## 新增：`format: "json"`

`kb_list` / `kb_read` / `kb_search` / `kb_backlinks` / `kb_diag` 都接受 `format: "json"`：把 execute 已经算好的结构化字段直接给模型（`tid/source/lines/chars/hits`、diag 的 `{errors, warnings, advice, exit_code}`），不再折叠成散文再让 Agent 正则切回来。

`kb_diag` 在 json 模式下**不抛异常**：成败看 `exit_code`，这样 Agent 可以「有 error 就停、只有 warning 就继续」。

## 新增：散文 / 行内代码里的 TID 核对

`lib/engine/tidref.js`（`staleTidWarnings`）+ `diag.js` 接线，新增两类 warning：

- `不可解析的 TID 文本: <哪个节点> 文件第 N 行「<token>」；最接近: …`
- `TID 大小写不合规: … 「doc:01-REAL」→ 应写「doc:01-real」`

口径（宁可漏报、不误报）：只看围栏外的行；先抹掉真引用 `[[…]]`、URL、markdown 链接目标；token 的命名空间必须是本库真实存在的（某个 TID 的首段、目录 `type`、`root`）；`×`/`✗` 开头的反例、占位符（`doc:x`）、路径样子的 `doc/03-build.md`、别的命名空间都不报；行号按**文件行号**报（对齐 `node.lines`）。

`diag_ignore.json` 新增第三项 `tids`，只压这两条（匹配 token 本身）。

实测：`about-comfyui` 报出两处 `doc:Blender白模导出` → 应写小写；`about-ros2` 报出 `lessons:04-guest与SSH`；`about-rl-project` 报出 `todo:002-已关闭`、`doc:02`、`doc:00`、`todo:002` 四处失效文本。这些都是各库自制脚本当初在查的同一类问题。
