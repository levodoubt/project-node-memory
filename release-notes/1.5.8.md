# 1.5.8

反馈 8（在别人的真实库上实测 1.5.7）的六条：五个界面/语义问题 + 一处**静默坏树**。

## 一个库两套名字，`kb_list` 只报一套

发现出来的名字（技能目录名、`about-xxx` 这类）和注册表里的名字（`filmmeasure` 这类）指向同一个 `.nodekb` 时，
`listLibraries` 以前会**整行丢弃**注册项——于是 `kb=` 能用的名字在 list 里根本看不见，`plugin-updated` 也
只挂在其中一个名字下（实际它按 `.nodekb` 路径记，本来就该是同一个库）。

- `lib/engine/registry.js`：`listLibraries` 增加 `byNodekb` 映射与 `aliases: []`；注册项若指向已发现的库，
  名字并进那一行的 `aliases`，不再丢弃。
- `lib/host/tools.js`：`kb_list` 渲染成 `- <发现名>  <路径>  （别名：<注册名>）`。
- `hidden: true` 的语义不变（只作别名、不进列表）；`includeHidden` 时才作为独立行列出。

## 默认 `parent` 是静默陷阱（会悄悄长出一条错树）

老规则：同文件第 2 个及以后的 `<node>` 缺省挂到「本文件第一个 `<node>`」下面。后果是用户按技能写法平铺
几个同名结构的 `<node>`（`doc/06-踩坑与教训` 的 `20.1`–`20.7` 那种），整片全串成一条链——TID 可引用、
引用不报错，只是树是错的，而且**没有任何提示**。

- `lib/engine/mdlib.js`：删掉 `first_node_tid` / `default_parent`；缺省父由**结构**决定——
  文件级写开的 `<node>` → 文件节点（彼此并列兄弟）；写进另一个 `<node>` 里的 → 那个外层节点。
- 想嵌套就把标签写开（真正的嵌套），想并列就平铺；显式 `parent="…"` 仍然优先。

## `###` 不建节点，文档却写「`#`/`##`（及更深）」

`write.js` 的段边界只认 `#` / `##`，`###` 属段正文；但随包技能里写成「只认围栏外、`#`/`##`（及更深）的标题行」。
照文档写的 `[[node="doc:01-probe:1.1"]]` 必然悬空（报「前缀指向不存在的节点」），人得先失败一次才知道。

- `skills/project-node-memory-guide/SKILL.md`：改成「只认 `#` / `##`；`###` 及更深不建节点、也不切段」，
  并点明别写 `doc:x:1.1` 这种引用。

## 长段阈值两套口径

文档与 SKILL 都没写 `longSection` = 10000（`dsh-nodekb/README.md` 写了，技能里没有），advice 本身也不提阈值。

- `lib/engine/advice.js`：`long-section` 的 message 改成「N 个段节点超过 <阈值> 字符（阈值 advice.longSection，可配）：最大的 3 个」；
  `fix` 点明「按 `##` 拆（`###` 不建节点，拆了还是同一段）」。
- SKILL 增一节 advice 阈值表（`minFragNodes 10` / `fragChars 500` / `longSection 10000` / `maxItems 5`），并写明可在插件配置
  `advice: { … }` 覆盖。

## `kb_init` 一律铺四件套

- `lib/engine/scaffold.js`：`SEEDS` 带分组，`scaffold(dir, { parts })` 只铺要的组；`README.md` 与 `diag_ignore.json` 总是铺；
  没铺 `doc` 时 `index/entry.md` 换成不引用 `doc:00-overview` 的版本（否则新库自带一条悬空引用）。
- `lib/host/tools.js`：`kb_init` 新增 `parts: ["doc","index", …]` 参数（缺省四件套全铺）。
